# Project Evidence Log

## Назначение

Этот файл нужен как накопительный журнал серьёзности подхода:

- что уже было сделано
- что уже было проверено
- какие решения были приняты осознанно
- на каком наборе звонков уже калибровалась модель

Этот файл пригодится для:

- handoff-пакета
- внутреннего ревью
- аргументации перед CloudCode
- аргументации, почему модель строилась не как “сырое MVP”, а как серьёзный рабочий продукт

## Архитектурные решения

### Изоляция проекта

- Создана отдельная рабочая копия:
  - `call-analyzer-codex`
- Основной проект `call-analyzer` не трогался

### Разделение пайплайна

Система разбита на отдельные слои:

- `transcription`
- `fact extraction`
- `normalization`
- `rule engine`
- `reporting`
- `storage`

### Сохранение артефактов

По каждому звонку уже сохраняются:

- `transcript.json`
- `facts.json`
- `report.json`
- `metadata.json`

Это позволяет:

- пересчитывать логику без повторной транскрибации
- не тратить деньги повторно на уже пройденные звонки
- передавать результат на внешнее ревью без нового прогона аудио
