# Call Analyzer Codex

Локальная версия анализатора звонков для пакетной обработки аудиофайлов через Streamlit.

## Что нужно для запуска

- Python 3.10+ или 3.11
- `ffmpeg`
- ключ `ANTHROPIC_API_KEY`
- ключ `OPENAI_API_KEY`

## Что делает приложение

1. Берёт аудиофайлы из загрузки или из папки на диске
2. Транскрибирует каждый звонок через OpenAI `gpt-4o-mini-transcribe`
3. Анализирует транскрипт через Claude
4. Сохраняет результаты в папку `results/`
5. Показывает историю и сводный отчёт в локальном сайте

Количество звонков не фиксировано: можно обрабатывать любой батч, который укладывается в ваши лимиты API и время ожидания.

python3 -m venv .venv

```bash
python3 -m streamlit run app.py
```

Обычно Streamlit поднимается на:

- `http://localhost:8501`

## Ключи API

- `ANTHROPIC_API_KEY` нужен для анализа звонка и формирования оценки
- `OPENAI_API_KEY` нужен для транскрибации аудио

## Клиентский контур

- У каждого клиента теперь может быть свой `ID клиента`
- Это нужно, чтобы данные разных застройщиков не смешивались
- Для нового клиента приложение может подготовить шаблон:
  - отдельную папку `reference/<client_id>/`
  - отдельную папку `results/<client_id>/`
  - отдельную папку `artifacts/<client_id>/`
- В шаблон автоматически входят:
  - `client_policy.json`
  - `jk_names.txt`
  - `jk_aliases.json`
  - `expert_overrides.json`

Для текущего исторического клиента сохранена мягкая совместимость через `default`.

## Справочник ЖК

- Базовый словарь ЖК лежит в `reference/jk_names.txt`
- Он подхватывается автоматически при запуске приложения
- Дополнительные названия для конкретного батча можно дописать в настройках интерфейса
- Для отдельного клиента можно хранить собственный словарь в `reference/<client_id>/jk_names.txt`

## Политика клиента

- Базовая клиентская политика лежит в `reference/client_policy.json`
- Там задаётся логика воронки и допустимые типы встреч
- При необходимости этот файл можно менять под конкретного застройщика без переписывания кода
- Для отдельного клиента можно хранить свою политику в `reference/<client_id>/client_policy.json`

## Артефакты обработки

- Помимо итоговых `results/`, приложение сохраняет промежуточные артефакты в `artifacts/`
- Это нужно, чтобы позже можно было пересчитывать правила и отчёты без повторной транскрибации

## Важные замечания

- Если файл слишком большой, приложение пытается сжать его через `ffmpeg`
- Результаты сохраняются локально в `results/<client_id>/`
- Один и тот же звонок сейчас определяется по ID файла и может быть пропущен как уже обработанный

## Основные страницы

- `app.py` — загрузка и анализ звонков
- `pages/history.py` — история обработанных звонков
- `pages/report.py` — сводный отчёт для застройщика
